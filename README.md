# B3-2 Mini Git

커밋·브랜치·HEAD를 메모리에 관리하며 그래프 탐색과 역색인을 배우는 CLI 프로그램입니다. 첨부된 B3-2 미션 PDF의 필수 기능을 구현했습니다. 실제 파일 내용은 추적하지 않으며 종료하면 데이터가 사라집니다.

## 1. 파일 구조와 처리 흐름

| 파일 | 역할 |
| --- | --- |
| `main.py` | 실행 시작점, 따옴표를 고려한 입력 파싱, REPL, 결과 출력 |
| `repository.py` | 커밋 모델, 브랜치·HEAD·커밋 상태, 알고리즘 연결 |
| `algorithms.py` | 안정 병합 정렬, Kahn 위상 정렬, DFS 조상 탐색, BFS 최단 경로 |
| `index.py` | 키워드·작성자 역색인 등록 및 조회 |


`main()` → `execute()` → `Repository` → 알고리즘/역색인 → `main.py` 화면 출력 순서입니다. 조회 함수는 결과를 반환하고 화면 출력은 CLI에서 담당합니다.

## 2. 실행 환경

- Python 3.10 이상, 외부 패키지 설치 불필요
- Python 표준 라이브러리: `shlex`, `dataclasses`, `datetime`, `collections.deque`


## 3. 빠른 시작

Windows PowerShell:

```powershell
cd .\B3-2-mini-git
python main.py
```

Linux/macOS 터미널:

```bash
cd B3-2-mini-git
python3 main.py
```

이후 `mini-git>` 프롬프트에 아래 명령을 **한 줄씩** 입력합니다. `mini-git>` 자체는 입력하지 않습니다.

```text
INIT "Alice Kim"
COMMIT "Initial commit"
BRANCH feature
SWITCH feature
COMMIT "Add login feature"
SWITCH main
COMMIT "Add payment feature"
LOG
PATH 00000002 00000003
ANCESTORS 00000003
SEARCH "login"
SEARCH "add feature"
SEARCH --author="Alice Kim"
LOG --sort-by=date
LOG --sort-by=author
QUIT
```

## 4. 명령어

| 명령 | 동작 |
| --- | --- |
| `INIT <user_name>` | main과 현재 사용자 설정. 첫 커밋 전 HEAD의 커밋은 없음 |
| `BRANCH <branch_name>` | 현재 커밋을 가리키는 브랜치 생성. 자동 전환하지 않음 |
| `SWITCH <branch_name>` | 현재 브랜치 전환 |
| `COMMIT <message>` | 현재 브랜치의 커밋을 부모로 새 커밋 생성, 역색인 갱신 |
| `LOG` | 전체 저장소의 커밋을 부모가 자식보다 먼저 나오도록 출력 |
| `LOG --sort-by=date` | timestamp 오름차순 |
| `LOG --sort-by=author` | 작성자 이름의 Python 문자열 비교 순서로 오름차순 |
| `PATH <commit1> <commit2>` | 부모 연결을 무방향으로 본 최단 경로. 없으면 `No path` |
| `ANCESTORS <commit_hash>` | 자기 자신을 제외한 모든 조상. 중복 없이 DFS 방문 순서 |
| `SEARCH <keyword>` | 소문자·공백 분리 토큰으로 메시지 역색인 검색 |
| `SEARCH --author=<name>` | 작성자 전체 이름으로 역색인 검색 |
| `HELP` | 명령 목록 |
| `EXIT` / `QUIT` | 프로그램 종료 |

### 문법·동률·검색 규칙

- 명령어는 대소문자를 구분하지 않습니다. `commit`, `CoMmIt`도 같습니다.
- 옵션 이름과 값은 표에 적힌 소문자를 사용합니다. 브랜치명·작성자명은 대소문자를 구분합니다.
- 공백이 있는 사용자명, 브랜치명, 메시지, 검색어는 따옴표로 감쌉니다. `SEARCH --author="Alice Kim"`도 인자 하나로 해석합니다.
- 빈 문자열이나 공백뿐인 인자는 `Invalid args`입니다. 공백 문자열을 허용하기 위해 `shlex.split()`을 사용합니다.
- 키워드는 **부분 문자열이 아니라 단어 전체**와 비교합니다. `login`은 `LOGIN`과 일치하지만 `log`나 `login,`과는 다릅니다. 구두점은 제거하지 않습니다.
- 여러 단어 검색의 결합 방식은 원문에서 정하지 않았으므로 **모든 단어가 있는 AND 검색**을 채택했습니다. `SEARCH "add login"`은 순서와 관계없이 두 토큰이 모두 들어간 메시지를 찾습니다.
- 검색 결과는 커밋 생성 순서입니다. 같은 메시지에 `login login`이 있어도 해당 커밋은 한 번만 나옵니다.
- 기본 LOG의 독립된 노드 간 순서는 생성 순서로 큐에 들어오는 순서를 따릅니다. 전체 커밋 생성 순서와 항상 같다는 뜻은 아닙니다.
- 옵션 LOG의 키가 같으면 기존 생성 순서를 보존합니다. **옵션 정렬은 부모 우선 보장을 따로 적용하지 않습니다.**
- 최단 경로가 여러 개면 `hash1->hash2->...` 문자열의 사전순이 가장 작은 경로를 고릅니다. 출력에 보이는 화살표 양쪽 공백은 가독성용입니다.
- hash는 `00000001`부터 증가하는 16진수 식별자입니다. 최소 8자리이며 8자리를 넘어도 잘라내지 않습니다. 세션 내 중복이 없고 암호학적 내용 해시는 아닙니다.

## 5. 범위와 주의사항

- `INIT` 재입력은 `Repository already initialized`로 거부하여 기존 데이터를 보존합니다. 초기화하려면 종료 후 다시 실행합니다.
- 원문의 사용자 변경 명령은 없으므로 CLI 세션에서는 INIT에 지정한 작성자를 계속 사용합니다. 작성자 정렬은 구현되어 있고 서로 다른 작성자는 모델 데이터로 별도 검증했습니다.
- 첫 커밋 전에 브랜치를 만들면 서로 독립된 루트 커밋을 생성할 수 있습니다. 이 경우 두 루트 사이 PATH는 `No path`입니다.
- 모델의 `parents`는 여러 부모를 담을 수 있고 탐색도 지원하지만 필수 COMMIT은 부모가 최대 하나입니다. 보너스 `MERGE`, `DIFF`, 정렬 성능 비교는 구현하지 않았습니다.
- 파일 내용 추적, 네트워크 통신, 데이터 파일 저장은 구현 범위에 포함하지 않습니다. 실제 Git 저장소의 파일을 수정하지 않습니다.
- 메모리나 사용자 인터페이스의 동시 접근을 제어하는 실제 서비스용 설계는 포함하지 않습니다.

## 6. 오류 해결

| 출력/문제 | 원인과 해결 |
| --- | --- |
| `Repository not initialized` | 먼저 `INIT "이름"` 실행 |
| `Invalid args` | 인자 개수, 빈 값, 따옴표 짝, 옵션 확인 |
| `Unknown branch: name` | `BRANCH name`으로 만든 브랜치만 SWITCH 가능 |
| `Branch already exists: name` | 이미 있는 이름. 다른 이름으로 생성 |
| `Unknown commit: hash` | COMMIT 결과나 LOG에 나온 전체 hash 사용 |
| `Unknown command: name` | HELP로 지원 명령 확인 |
| `No commits` | 저장소/조회 결과가 비어 있음. 오류가 아님 |
| `No path` | 두 커밋은 있지만 서로 다른 연결 요소에 속함 |
| 재실행 후 커밋이 없음 | 메모리 방식의 정상 동작 |
| `main.py`를 찾을 수 없음 | `main.py`와 다른 `.py` 파일이 같은 폴더인지 확인 |

오류를 출력한 뒤에도 다음 명령을 받을 수 있습니다. EOF 또는 Ctrl+C도 정상 종료로 처리합니다.

## 7. FAIL 평가 항목별 구현 근거와 분석

아래 설명은 현재 코드의 동작을 기준으로 합니다. 항목별 연속 인용과 코드 위치는 [평가 보완 제출 자료](docs/evaluation_evidence.md)에 정리했습니다. 개선 제안은 현재 구현과 구분하여 표시합니다.

### 항목 #2: BRANCH · SWITCH · COMMIT

`BRANCH <name>`은 현재 브랜치가 가리키는 커밋 hash를 새 브랜치에 복사하며 현재 브랜치는 바꾸지 않는다. `SWITCH <name>`은 존재하는 브랜치인지 확인한 뒤 `current_branch`를 해당 이름으로 바꾼다. `COMMIT <message>`는 현재 브랜치의 기존 커밋을 부모로 새 Commit을 생성하고, 커밋 저장소·그래프·역색인에 등록한 뒤 현재 브랜치가 새 hash를 가리키도록 갱신한다.

예를 들어 `INIT Alice` → `COMMIT first` → `BRANCH feature`까지 실행하면 main과 feature는 모두 `00000001`을 가리키고 현재 브랜치는 main이다. 이어서 `SWITCH feature` → `COMMIT second`를 실행하면 현재 브랜치는 feature이며, feature만 `00000002`로 이동하고 main은 `00000001`에 남는다.

### 항목 #6: SEARCH · --author · LOG --sort-by

`SEARCH <keyword>`는 메시지를 소문자·공백 기준 토큰으로 비교하는 키워드 역색인을 사용하며 여러 단어는 AND 조건으로 검색한다. `SEARCH --author=<name>`은 `--author=` 접두사를 제거한 작성자 전체 이름을 작성자 역색인에서 대소문자까지 일치시켜 조회한다. `LOG --sort-by=date`와 `LOG --sort-by=author`는 각각 timestamp와 author를 키로 직접 구현한 안정 병합 정렬을 적용하며, 다른 정렬 값은 `ValueError("Invalid args")`로 거부한다.

### 항목 #8: 커밋 hash · 해시 맵 · 중복과 충돌

커밋 hash는 `next_commit_id`를 1부터 증가시키며 최소 8자리 16진수 문자열로 변환한 식별자이고, `self.commits`라는 dict 해시 맵에 `hash → Commit`으로 보관한다. 정상적인 Repository API 사용에서는 카운터를 재사용하지 않고 자리수가 늘어나도 자르지 않으므로 같은 세션에서 식별자가 중복되지 않는다. 이 식별자는 내용 기반 암호학적 해시나 난수가 아니며, Python dict 내부의 해시 충돌은 키 동등성 비교로 구별된다. 같은 식별자 문자열을 다시 넣는 중복 검사는 별도로 없으므로 외부에서 카운터를 임의로 되돌리면 기존 항목을 덮어쓸 수 있다.

### 항목 #12: 사이클 검출 · Commit 불변성

`topological_order`는 Kahn 위상 정렬 후 처리한 노드 수가 전체 커밋 수와 다르면 `raise ValueError("Cycle detected")`로 사이클을 알린다. `Commit`은 `@dataclass(frozen=True)`로 선언되고 `parents`는 tuple이므로 일반적인 필드 대입이나 부모 목록 변경으로 기존 이력을 수정할 수 없다. 현재 COMMIT API는 기존 노드를 수정하지 않고 새 노드가 기존 커밋을 부모로 참조하게 하여 사이클 생성을 방지한다. 다만 저장소의 dict와 그래프 목록 자체를 불변으로 만드는 설계는 아니며, 사이클 검출은 이 자료구조들이 일관된 그래프를 나타낸다는 전제를 따른다.

### 항목 #13: 기본 LOG의 위상 정렬과 부모 우선 순서

옵션 없는 기본 `LOG`는 전체 저장소에 Kahn 위상 정렬을 적용하며, 부모가 모두 출력되어 남은 부모 수가 0이 된 커밋만 큐에 넣으므로 모든 부모를 자식보다 먼저 출력한다. 서로 조상·자손 관계가 없는 커밋 사이에서는 큐에 들어온 순서를 따르며 전체 생성 순서까지 보장하지는 않는다. `LOG --sort-by=date|author`는 별도의 키 정렬이므로 기본 LOG의 부모 우선 보장을 적용하지 않는다.

### 항목 #14: PATH의 BFS · 무방향 · 최단 경로

`PATH`는 부모와 자식 양쪽을 이웃으로 등록한 무방향 그래프에서, 가중치 없는 간선 수가 최소인 최단 경로를 BFS로 구한다. `shortest_path`는 목적지에서 역방향 BFS로 거리를 계산한 뒤 출발지에서 거리가 1씩 줄어드는 이웃을 골라 경로를 복원한다. 최단 경로 동률이면 공백 없는 `hash1->hash2->...` 문자열의 사전순으로 선택하고, 연결되지 않으면 빈 목록을 반환하여 CLI가 `No path`를 출력한다. 출발지와 목적지가 같으면 해당 hash 하나를 반환하며, 존재하지 않는 hash는 탐색 전에 오류로 처리한다.

### 항목 #16: 역색인 구조 · 조회 복잡도 · 순회와 비교

`InvertedIndex`는 `keywords: 단어 → hash 목록`, `authors: 작성자 → hash 목록`의 두 dict로 구성되며, `dict.get`으로 특정 키의 후보 목록을 찾는 연산은 평균 O(1)이다. 이는 문자열 해싱 비용을 별도로 보는 평균 복잡도이며 전체 검색 결과를 만드는 시간이 O(1)이라는 뜻은 아니다. 키워드 검색은 후보 목록들을 set으로 변환한 뒤 가장 짧은 목록만 순회하고 각 hash가 모든 set에 속하는지 비교한다. 고유 검색 단어 수를 k, 각 후보 목록 길이를 Lᵢ, 최단 목록 길이를 m이라 하면 토큰화 이후 평균 시간은 O(k + ΣLᵢ + k·m)이고, 작성자 검색은 결과 r개의 목록 복사 때문에 O(r + 1)이다. Repository는 검색된 hash만 `self.commits`에서 조회하며 전체 커밋을 별도로 순회하지 않는다.

### 항목 #17: 규모 증가 시 병목과 개선 방향

현재 구현은 커밋 V개와 부모 간선 E개를 메모리에 보관하며, 기본 LOG와 PATH의 그래프 탐색 시간은 O(V + E), 옵션 LOG는 키 비교 비용을 일정하게 볼 때 O(V log V)이다. 역색인의 전체 hash 등록 수를 P라고 하면 그래프와 인덱스 저장 공간은 메시지·키 문자열 자체의 크기를 제외하고 O(V + E + P)이며, 흔한 검색어의 긴 후보 목록은 조회마다 set을 만드는 시간과 임시 메모리의 병목이 된다. 개선안으로는 정렬된 후보 목록의 교집합 또는 비트맵 사용, 영속 저장소와 결과 페이지 처리, 반복 조회 캐시를 검토할 수 있다. 더 큰 규모에서는 단어·작성자 키별로 인덱스를 분산하고 여러 단어의 후보 교집합을 조정하는 계층을 둘 수 있으나, 커밋 저장과 인덱스 갱신의 일관성 및 분산 결과의 순서 유지도 함께 설계해야 한다. 이 개선안과 인덱스 분산은 현재 구현되지 않았다.

### 항목 #18: 카운터와 난수 · 재현성 · 테스트 고려사항

현재 hash 생성은 난수 대신 증가 카운터를 사용하므로 새 Repository에서 같은 순서로 정상 COMMIT을 실행하면 같은 hash와 부모 관계를 재현할 수 있다. 다만 timestamp는 `datetime.now(timezone.utc)`이므로 실행마다 달라지고 전체 출력까지 동일하지는 않다. 테스트에서는 hash·부모·브랜치 이동을 고정된 기대값으로 비교하되 시각은 별도 검증하거나 시계를 고정해야 한다. 난수 식별자로 변경한다면 충돌 확인과 재시도가 필요하고, 테스트는 난수 생성기 주입이나 반환된 식별자에 기반한 비교로 바꿔야 한다. 현재 카운터 식별자는 다른 세션에서도 다시 1부터 시작하므로 세션 간 전역 유일성은 보장하지 않는다.
